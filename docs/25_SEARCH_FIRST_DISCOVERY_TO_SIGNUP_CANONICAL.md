# 25 Oct 2026 — FOUNDER'S CANONICAL SEARCH-FIRST PRODUCT FLOW

**Status: approved product requirement / engineering target, NOT a completed working feature.** This document supersedes any older sentence suggesting Shopify-first onboarding, that a login is required before the first public research report, or that a read-only Shopify dashboard constitutes Ayo's whole first release.

## Core journey (must be the homepage, not a secondary tab)
1. Public visitor sees one dominant business discovery field: **Search for your business**. Accept name + country/city and/or a safely normalized public website URL; search results show matching real candidates with disambiguation. No Shopify requirement, no account required to begin discovery.
2. Ayo retrieves publicly accessible, permitted source content (business website, pages, products, policies, social/business listing links that are accessible through lawful providers) using an SSRF-hardened crawler or verified search/data APIs. Respect access restrictions, rate limits, content licensing and platform terms. Distinguish independently verified URL from a possible name match. For merchants without websites, a business name, location, public business listing or owner-supplied facts start a bounded assessment. Always allow 'not enough public information' results.
3. An assessment record stores facts with per-claim source URL, captured date, excerpt, confidence, attribution, freshness and research limits. LLM output is derived from **retrieved evidence**, not merely a merchant's name. External content is untrusted data (prompt injection must not authorize tools). Generate a **short, useful public mini-report**: what the company appears to sell, accessibility/UX observations, positioning, opportunities with rationale, verified potential B2B lead candidates if sourced, and unknowns. Only claim contacts where legally and factually justified. Show no fabricated revenue, sales, customer lists, employee counts, conversion rates or paid ads.
4. The mini-report ends in a genuine **Create free account / Claim this business** action, not an integration paywall. Store anonymous research under short-lived opaque, non-guessable token with TTL, privacy controls, quotas, no secrets; creating an account securely attaches that report to the authenticated user ONLY after appropriate claim/ownership proof. Merely searching a company must NEVER give control over its data, impersonation, messaging, profile, or provider account.
5. After user account creation, show saved mini-report, evidence and next steps. Business ownership verification happens before attaching the public company profile to the private controlled organization. Allow user to create a separate unverified workspace with clear labels if proof is not yet provided. Ayo can start **draft-only, sourced lead discovery and research** without Shopify. Lead acquisition uses permitted discoverability and lawful contact rules; no invented phone/email, no indiscriminate scraping, and no messages without authorization/compliance checks.
6. Integrations are optional accelerators INSIDE Business → Connections: Shopify first provider adapter, then regionally appropriate WooCommerce, custom storefront, payments and social/seller channels. Shopify OAuth grants store data access only through that merchant's own Ayo app install. If not configured, honest 'Setup required' state. Connected data expands analysis; it is not the condition for public research or first account.
7. Ayo's unified intelligence takes measured actions through specialized skills: Observe → verify evidence → Diagnose → Recommend → Draft → merchant approve + lawful provider checks → Execute through deterministic provider adapter → Verify outcome. At every layer distinguish discovered leads, qualified leads, contactable prospects, sent outreach, actual responses, opportunities and verified sales.

## African merchant UX rules
- Launch focus: Nigerian and Ghanaian ecommerce sellers. Design for storefronts and public business profiles, WhatsApp/Instagram-led merchants, scarce structured product feeds, NGN/GHS, bank transfers, local payment methods, unreliable web footprints and mobile-first usage. Do not assume a social URL is crawlable; implement an owner-assisted path if blocked.
- Country must be chosen/verified; locale never inferred from race, name or browser region. Cross-border sellers can select more than one market; currency and payment state originate from authorized provider records.
- Research reports must be actionable and culturally/market relevant, not generic imported conversion checklists. Avoid confident but unverified geographic and competitor assertions.

## AI provider decision and operations
- Proposed starting primary: **Gemini**, for available grounding/search + URL context, with **Claude as a swappable optional model** for complex multi-step reasoning. This is a recommendation, not an implemented integration or a measured comparative winner. Provide server-side model gateway, typed tool permissions, grounding citations, prompt-injection resistance, budgets, eval harness, cost telemetry, fallbacks and vendor-neutral persisted evidence.
- Search engine/provider and crawl pipeline are independent of the reasoning model. Never make the LLM a general network agent, grant it write credentials, or claim its grounded answer alone proves lead legitimacy. Follow official SDK/API docs at implementation time.
- Evaluate models using a Nigerian + Ghanaian benchmark: real-company disambiguation, site retrieval quality, product and competitor accuracy, leads with verifiable source, hallucination rate, locale performance, latency, and total per-onboarding cost. Make deployment gating evidence-based.

## Free access rule
**Exactly as founder requested: ALL Ayo features FREE for ALL of the FIRST 500 DISTINCT CUSTOMER USER ACCOUNTS.** No premium features or paid capabilities for that cohort; newly shipped Ayo features also available free. This is not a trial, and there is no automatic downgrade/expiry. Explicit third-party charges, safety/consent, anti-abuse and provider permission checks remain separate. Quotas can protect infrastructure but cannot masquerade as paid feature unlocks. Later-user pricing requires founder approval.

## Acceptance scenarios
- Unauthenticated Nigerian user searches a real business name; disambiguates from similarly named companies; sees sources, freshness, confidence and a useful mini-report BEFORE registering.
- Ghanaian small merchant with no Shopify enters a public site or business-name/location and obtains research + lead candidates (when genuinely discoverable), creates an account and sees saved research.
- Same journey with no website and blocked public social profile: honest limitations + guided owner-supplied assessment, no fake website.
- User registers with a valid email; anonymous research cannot be hijacked by another user's claim. Business owner verification precedes private provider access.
- Shopify credentials missing: the rest of search, mini-report, signup, and lead research still work; Shopify shows an explicit optional 'not configured' state.
- Fake/malicious URL, local/private IP, DNS rebinding, redirect to internal IP, oversized response, prompt injection, duplicate lead, opt-out contact: blocked or safely handled, tested.
- No sourced leads found: clear 'none verified yet', not an invented contact.
- Two independent user accounts cannot access each other's reports, businesses, tokens, leads, outreach drafts or analytics.
- 500 founding user entitlements granted transactionally; first 500 can open ALL actually implemented features, no paywall, including later features. 501st has no pricing applied until founder approves.
